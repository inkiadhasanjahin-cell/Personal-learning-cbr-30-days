1. What Is a Jeopardy-Style CTF?

A Capture The Flag (CTF) competition is a security exercise where you solve challenges to find a hidden secret string — the flag — and submit it for points. There are two dominant formats:

🏆 Jeopardy-style

A board of independent challenges grouped into categories, exactly like the TV game show. Teams pick any challenge, solve it, submit the flag, earn points. No direct interaction with other teams' systems. This is the format used by picoCTF, HackTheBox CTFs, DEF CON quals (mostly), and nearly every beginner/intermediate CTF.

⚔️ Attack-Defense

Each team runs identical vulnerable services on their own machine. You must patch your own bugs while exploiting the same bugs on opponents' machines to steal their flags. Real-time, much harder to run and to play. Not the focus of this note.

The Board

Picture an actual Jeopardy board: columns are categories (Web, Crypto, Pwn...), rows are point values that usually track difficulty (100 → easy, 500 → hard). You choose challenges in any order — there's no forced sequence, which means triage (deciding what to attempt first) is itself a skill.

Key mental model: a jeopardy CTF is really just a stack of independent puzzle boxes. Each category tests a different skill domain. You don't need to be good at all of them — most teams specialize and trade challenges internally.

Typical Event Structure

  • Duration: anywhere from a few hours (local/university CTFs) to 48 hours (major international ones like DEF CON, HITCON, or Google CTF).
  • Team size: solo or teams up to ~4-8, depending on the event's rules.
  • Platform: a scoreboard site (CTFd is the most common open-source platform) shows live rankings, challenge descriptions, attached files or connection strings (nc host port), and a flag submission box.
  • Hints: often available but cost points when unlocked.

2. Flag Formats

The flag is a string that proves you actually solved the challenge (rather than just claiming you did). Almost every platform wraps the secret content in a recognizable wrapper format so that:

  • Automated scoring can validate submissions with a simple regex.
  • Players can visually confirm "yes, this looks like a flag" before submitting.
  • Copy-paste errors (extra whitespace, wrong case) are easier to spot.

Common wrapper conventions

Event / PlatformFormatExample
picoCTFpicoCTF{...}picoCTF{f14g_h4x0r_42}
HackTheBoxHTB{...}HTB{y0u_f0und_m3}
Generic / most CTFd eventsflag{...} or CTF{...}flag{s0_that5_1t}
DEF CON styleOften no wrapper — a raw stringd3fc0n_2026_x9k2
Anatomy: flag{ this_part_is_the_secret } — the braces and prefix are constant per-event; only the inside changes per challenge. Some events randomize the wrapper's inner casing or add a checksum suffix to prevent flag-sharing between teams (called a dynamic or per-team flag).

Why the format matters practically

  1. Sanity check: if your exploit outputs something that doesn't resemble flag{...}, you probably haven't reached the actual secret yet — keep digging.
  2. grep-ability: once you know the format, you can search dumped memory, files, or network captures directly: grep -a -o "flag{[^}]*}" dump.bin.
  3. Case & whitespace sensitivity: most scoring engines do an exact string match. Trailing newlines or a stray capital letter will cause a "wrong flag" even if you solved the challenge.
Common beginner mistake: submitting only the inside content without the flag{ } wrapper, or including the challenge's example placeholder text by accident. Always read the challenge description for the exact required format — it's usually stated explicitly.

3. Scoring Systems

Two scoring philosophies dominate jeopardy CTFs:

A. Static Scoring

Each challenge has a fixed point value set by the organizers ahead of time, based on their estimate of difficulty. Simple, predictable, but can misjudge difficulty (a "500-point" challenge that turns out to be easy devalues harder ones once everyone solves it).

B. Dynamic ("Decay") Scoring

A challenge starts at a high value and decreases as more teams solve it, following a curve (often set by minimum points, maximum points, and a decay function based on solve count). This rewards being among the first solvers and self-corrects for misjudged difficulty — a challenge everyone finds easy naturally drops toward its floor value.

A common CTFd decay formula (simplified):
points = max(minimum, initial − ((initial − minimum) / decay_constant) × (solves − 1))
In plain terms: the more teams that solve it, the closer it falls toward the floor value.

Bonus mechanics you'll see layered on top

MechanicWhat it does
First BloodExtra bonus points (or a badge) for the very first team to solve a challenge.
Hint penaltyUnlocking a hint deducts a fixed amount from that challenge's max value.
TiebreakerWhen total score ties, the team that reached that score earliest ranks higher.
Category multiplier (rare)Some events weight an entire category up/down to nudge diversity of skills.
Strategic takeaway: under decay scoring, solving something fast (before the crowd) is worth disproportionately more than solving it late. This is why strong teams "rush" easy/medium challenges in the first hour, then settle into harder ones once the board has thinned out.

4. The Major Categories

Nearly every jeopardy CTF board is built from some subset of these six pillars. Depth in even two or three of them is enough to be a strong contributor to a team.

🌐 Web Exploitation

Beginner-friendly

Attacking web apps: SQL injection, XSS, authentication bypass, IDOR, SSRF, insecure deserialization, template injection. Tools: browser dev tools, Burp Suite, curl.

🔐 Cryptography

Beginner–Advanced

Breaking or abusing weak/misused crypto: classical ciphers, RSA math attacks, weak randomness, hash length-extension, padding oracle attacks. Tools: Python, CyberChef, SageMath.

🧬 Reverse Engineering (RE)

Intermediate

Understanding compiled binaries without source: disassembling, decompiling, tracing logic to find a hidden check or the flag itself. Tools: Ghidra, IDA Free, gdb.

💥 Binary Exploitation (Pwn)

Advanced

Exploiting memory-corruption bugs in running programs: buffer overflows, format string bugs, ROP chains, heap exploitation, to hijack control flow and read a flag off a remote server. Tools: pwntools, gdb + pwndbg, checksec.

🕵️ Forensics

Beginner–Intermediate

Digging through artifacts: disk/memory images, packet captures (.pcap), file carving, steganography, metadata analysis. Tools: Wireshark, Autopsy, binwalk, exiftool.

🎲 Misc / OSINT

Grab-bag

Anything that doesn't fit elsewhere: puzzle logic, esoteric encodings, open-source intelligence (finding info about a person/organization publicly), scripting challenges, sometimes even trivia.

How categories map to skills you're already building

Your Python-for-cybersecurity track feeds directly into Crypto (scripting attacks) and Misc (automation/parsing), while your Linux roadmap underpins Forensics and Pwn (comfort with the command line, permissions, and debugging tools is assumed baseline in both).

5. Point Weighting in Practice

There's no universal rulebook, but across most beginner-to-mid-tier CTFs (picoCTF-style), a rough pattern holds: categories requiring lower-level systems knowledge (Pwn, RE) are weighted heavier per challenge because fewer teams can solve them, while categories with a large easy on-ramp (Web, Misc, Forensics) have more total challenges but a wider spread from very easy to very hard.

Bar length here represents relative typical difficulty ceiling, not literal point totals — exact numbers vary hugely by event. The pattern to internalize: Pwn > RE > Web ≈ Crypto > Forensics > Misc in terms of how high their point ceiling usually climbs.

Why organizers weight it this way

  • Solve-rate correlation: point value is a proxy for "how many teams are expected to solve this." Pwn/RE challenges typically have the lowest solve counts across an entire event.
  • Prerequisite stacking: Pwn challenges often require RE skills first (you must reverse-engineer the binary before you can exploit it), compounding difficulty and justifying higher value.
  • Category balance: organizers deliberately keep Misc/Forensics point ceilings lower so the scoreboard isn't dominated purely by teams with one narrow specialty.

6. Practice Zone

🧠 Concept Quiz (click to reveal answers)

Q1. In a decay-scoring CTF, why does solving a challenge in the first 30 minutes matter more than solving the same challenge 6 hours later?

Reveal answer
Because the point value decreases as more teams solve it — early solvers lock in a value close to the challenge's maximum, while later solvers get a value closer to the floor. The exact same solve is worth objectively fewer points later in the event.

Q2. You extract a string picoctf{maybe_this_1s_it} from a binary (lowercase, no closing detail issue). The event's rules state the format is picoCTF{...}. What's the most likely reason submission will fail?

Reveal answer
Case mismatch — picoctf vs the required picoCTF. Scoring engines usually do exact, case-sensitive string matching, so the prefix casing must match exactly even if the inner secret content is correct.

Q3. A challenge is tagged "500 points" and sits under the Pwn column. Based on typical point-weighting patterns, what does that placement + value tell you before you even open the challenge?

Reveal answer
It's likely near the top of the event's overall difficulty ceiling — Pwn challenges usually carry the highest point ceilings of any category because they require chaining RE + low-level exploitation skill, and solve rates tend to be very low.

Q4. What's the practical difference between Jeopardy-style and Attack-Defense CTF formats in terms of what you're defending?

Reveal answer
In Jeopardy-style, there is nothing to defend — you only solve independent challenges to extract flags. In Attack-Defense, you run a live vulnerable service that opponents can actively exploit, so you must simultaneously patch your own service while attacking theirs.

🧮 Exercise: Scoring Math

A challenge uses decay scoring: initial = 500, minimum = 100, decay_constant = 20. Using points = max(minimum, initial − ((initial − minimum)/decay_constant) × (solves − 1)), what is the challenge worth after the 6th team solves it?

Work through it / reveal answer
(initial − minimum) = 400. 400 / 20 = 20 points lost per solve after the first.
solves − 1 = 5 → 5 × 20 = 100 points decayed.
500 − 100 = 400 points for the 6th solver.
Try it yourself for the 25th solver — does it hit the floor of 100 before then? (400/20 = 20 → floor is reached once solves−1 ≥ 20, i.e. the 21st solver onward gets exactly 100.)

7. One-Page Cheat Sheet

Format Quick Facts

  • Flag = proof of solve, wrapped as tag{secret}
  • Match is usually exact & case-sensitive
  • grep pattern: grep -aoE "flag\{[^}]*\}"

Scoring Quick Facts

  • Static = fixed value, set upfront
  • Dynamic/decay = value drops as solves increase
  • First blood = bonus for first solver
  • Hints usually cost points

Category → Core Tool

  • Web → Burp Suite / browser devtools
  • Crypto → Python / CyberChef
  • RE → Ghidra / gdb
  • Pwn → pwntools / pwndbg
  • Forensics → Wireshark / binwalk
  • Misc → whatever the puzzle demands

Difficulty Ceiling Order

Pwn > RE > (Web ≈ Crypto) > Forensics > Misc

(rule of thumb, not universal)
